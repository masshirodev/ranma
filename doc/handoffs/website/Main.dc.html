A tiling window manager for the terminal.

i3's container tree and Hyprland's dwindle placement, where every window is a PTY. Sessions, workspaces, a floating layer and a scratchpad, driven by a leader key and a modal WM mode, configured in Lua and themed in TOML.

The leader is Ctrl+b, the key tmux uses.

Press it and let go, and ranma enters WM mode: the keys you press now go to ranma instead of the program in the pane. Wait half a second and a panel lists what each key does. Esc leaves it.

The leader is a setting, like everything else: ranma.set { leader = "ctrl+a" }. man ranma-keys lists the rest.

What it does

A daily driver: every milestone of the roadmap is done. Six panels, the way the README groups them.

1 · tiling

Panes place themselves.

Dwindle splits the focused pane along its longer side, like Hyprland. Or group panes into tabs, float one over the tiling, keep a scratchpad, or lay a workspace out as niri's strip of scrolling columns. Window rules and saved layouts on top.

2 · sessions

Close the terminal. Nothing closes.

ranma runs as a server: closing the terminal, or losing SSH, only detaches, and ranma again picks up where you were. Workspaces and sessions with fuzzy switchers. An upgrade moves running servers to the new build without closing anything.

3 · copy mode

Copy from history, over SSH too.

Copy mode is alacritty's vi mode, with history search. What you yank reaches the system clipboard by OSC 52, from a pane on the far side of an SSH connection as well. Files paste into a pane that runs ssh.

4 · images and keys

The kitty protocols, both of them.

Images draw in panes with the kitty graphics protocol. The kitty keyboard protocol works both ways, so a program asking for exact keys gets them. Outside WM mode bytes pass through raw; a paste is trusted to bracketed paste, not guessed.

plugins

Plain Lua on the same API as init.lua, in Neovim's layout. hako comes with ranma and installs them; leader L, then B, browses the official list. A plugin that fails while loading is dropped whole; a watchdog stops one that hangs.

Configured in Lua, themed in TOML.

The configuration behind the screenshot, as it is in doc/examples/screenshot. Lua for behaviour, TOML for looks. Both are parsed strictly: a name ranma doesn't know is an error that names it.

ranma --dump-config prints the default, with every option documented.

Why not tmux, zellij or tuios?

They are good, and you may want one of them instead. ranma gets where it is mostly by refusing scope, not by out-engineering anyone.

tmux

Use tmux where it is already installed on every machine you touch. ranma keeps its leader, its five preset layouts and the things people style in it, and adds a window manager's tree: dwindle placement, a floating layer, a scratchpad. A tmux shim covers a stated subset for programs that drive tmux; matching tmux feature for feature is a non-goal.

zellij

zellij is a whole workspace with its own interface and WebAssembly plugins. ranma takes its shape from tiling window managers instead: i3's tree, Hyprland's placement, niri's columns. Its plugins are plain Lua on the same API as your init.lua.

tuios

tuios is the model for the feel. ranma aims to be the faster, less buggy daily driver by leaving things out:

  • one process, one copy of each grid, queues bounded by bytes
  • a server that owns everything and a client that holds nothing to desync
  • bytes pass through raw outside WM mode; bracketed paste is trusted, not guessed
what ranma refuses to be
  • Not reboot-proof. A snapshot brings back sessions, layouts and commands as new processes; the old ones are gone.
  • Not remote. No remote hosts, SSH or web servers, no clients keeping copies of the layout in step.
  • No AI in the core. A Lua hook can do that for someone who wants it.
  • Not native Windows. WSL2 is the Windows story. Not the BSDs yet either.
  • Not tmux. What it took from tmux it took in its own terms.

Then

Start it with ranma, and press Ctrl+b ? for every key. The man pages come with every install: man ranma, man 5 ranma, man ranma-keys.

After a package-manager upgrade

A package manager replaces the binary but doesn't check it or move servers. Shells and scrollback stay: ranma --check-config && ranma upgrade --all
